### 项目模块架构文档

该项目是一个基于 Bevy 引擎开发的贪吃蛇游戏。以下是项目的模块架构说明：

#### 目录结构概览
```text
src/
├── main.rs              # 项目入口，定义 App 配置、系统初始化、状态管理和系统运行逻辑
├── components.rs        # 定义 ECS 组件（Components）
├── constants.rs         # 定义游戏常量
└── systems/             # 游戏逻辑系统模块
    ├── mod.rs           # 模块导出文件，整合所有系统模块
    ├── snake.rs         # 贪吃蛇相关逻辑（移动、进食、生长、死亡）
    ├── environment.rs   # 环境相关逻辑（食物生成、陷阱生成）
    ├── ui.rs            # 用户界面逻辑（菜单显示、交互处理）
    └── render.rs        # 渲染相关逻辑（位置转换、尺寸缩放）
```

#### 模块详细说明

1.  **`main.rs` (核心控制层)**
    *   作为 Bevy 应用的配置中心。
    *   定义游戏状态 (`GameState`)。
    *   注册资源 (`Resources`) 和事件 (`Events`)。
    *   管理系统 (`Systems`) 的启动 (`Startup`) 和更新 (`Update`) 循环，并基于游戏状态运行不同的系统。

2.  **`components.rs` (数据定义层)**
    *   定义游戏中的数据结构 (`Components`)，用于 Bevy 的 ECS 模型。

3.  **`constants.rs` (配置层)**
    *   存放游戏通用的硬编码配置，如网格大小、颜色等。

4.  **`systems/` (业务逻辑层)**
    *   通过 `mod.rs` 暴露给主程序，按功能拆分为以下子模块：
        *   **`snake.rs`**: 负责处理贪吃蛇的移动输入、运动逻辑、进食判定、生长逻辑以及玩家死亡处理。
        *   **`environment.rs`**: 负责环境对象的生成逻辑，包括食物生成和陷阱生成。
        *   **`ui.rs`**: 处理所有 UI 相关的行为，包括暂停菜单、设置菜单的切换，以及界面内的按钮交互逻辑。
        *   **`render.rs`**: 负责将逻辑坐标转换为渲染位置，以及根据游戏对象的状态调整渲染大小。

这个框架逻辑清晰，按功能将系统划分为不同模块，符合 Bevy 的 ECS 最佳实践。
